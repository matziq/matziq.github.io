Domain 3 — Deploy AI-powered business solutions

Domain 3 is 20–25% of AB-100. It covers what happens after design: watching agents in production, testing them properly, moving them safely between environments, and keeping them secure, responsible, and compliant.

Monitor Testing ALM Governance Cheat sheet

3.1 Analyze, monitor, and tune AI solutions

  • Use telemetry (for example Application Insights) and built-in analytics in Copilot Studio to track sessions, resolution, escalation, abandonment, and errors.
  • Collect user feedback (ratings, comments) and turn it into a prioritized backlog of tuning work.
  • Tune instructions, topics, tool descriptions, and knowledge sources; review cost and model usage.
Exam trap

A spike in escalations or unanswered questions usually points to missing knowledge or poor topic/tool descriptions — measure first, then tune the specific gap.

3.2 Manage testing of AI solutions

TestPurpose
Defined metricsAgree on groundedness, relevance, accuracy, and task success targets before testing
Test sets / evaluationsRun representative and adversarial prompts repeatedly; compare versions
Custom model validationEvaluate fine-tuned or custom models against a held-out dataset and baseline
End-to-end scenariosExercise the full process across apps, agents, flows, and data
User acceptanceBusiness users confirm the solution meets the requirement

Generative output is non-deterministic, so test with many cases and score with metrics rather than expecting identical text.

3.3 Design ALM for AI solutions

  • Package Copilot Studio agents and related components in solutions; use separate dev, test, and production environments.
  • Use managed solutions downstream; use environment variables and connection references so settings change per environment without editing the agent.
  • Automate deployment with Power Platform pipelines or Azure DevOps / GitHub Actions; keep source control and versioning.
  • Apply the same discipline to Foundry Agent Service, custom models, data, and Dynamics 365 AI features: version, evaluate, promote, and be able to roll back.
Rule of thumb

Never edit directly in production. Build in dev, validate in test, promote a managed artifact.

3.4 Responsible AI, security, and governance

Security

  • Least-privilege access for agents, connectors, and service identities
  • Defend against prompt injection (direct and indirect) with content filters, input validation, and limited tool permissions
  • Data loss prevention (DLP) policies on connectors
  • Authentication on agents and channels

Governance and compliance

  • Environment strategy and managed environments
  • Data residency and retention requirements
  • Audit trails and activity logging
  • Sensitivity labels and Microsoft Purview controls

Microsoft’s six responsible AI principles

Fairness · Reliability and safety · Privacy and security · Inclusiveness · Transparency · Accountability. Expect scenario questions asking which principle a control supports (for example, disclosing that users are talking to AI supports transparency).
