Domain 2 — Design AI-powered business solutions

Domain 2 is 30–35% of AB-100. Planning chose what to build; design decides how: which agent type, how it understands and routes requests, how it reaches data and other systems, and when a prebuilt capability beats custom work.

2.1 Design AI and agents

Agent styleBehaviorGood for
Prompt-and-responseAnswers when a user asks; grounded Q&AHelp desks, policy lookup, knowledge assistants
Task agentCompletes a defined task with actions when askedCreate a case, book time off, update a record
Autonomous agentRuns from triggers (events, schedules) and acts within guardrails without a user promptTriage incoming email, monitor and respond to events

In Copilot Studio, topics define conversation paths; fallback handles what no topic matches; actions/tools call connectors, flows, prompts, or APIs. Design Dynamics 365 Copilot and customer-experience scenarios (sales, service, contact center) around the data already in Dataverse.

Exam trap

Autonomous agents need triggers, clear instructions, and guardrails — plus monitoring and human escalation. “Fully autonomous with no oversight” is rarely the right answer.

Understanding and orchestration

ApproachHow it routesChoose it when
Classic NLU / trigger phrasesMatches user input to topicsSmall, predictable, scripted conversations
Conversational language understanding (CLU)A trained Azure AI Language model maps intents and entitiesYou already have or need a custom-trained intent model
Generative orchestrationThe LLM chooses topics, actions, knowledge, and connected agents from their descriptionsMulti-step requests, many tools, natural phrasing

With generative orchestration, descriptions matter: clear names and descriptions for topics, tools, and agents are how the planner picks them. Agent flows add deterministic, repeatable steps where you don’t want the model improvising. Prompt actions wrap a reusable prompt as a tool.

Agents in apps and data processing

  • Embed agents in Power Apps, Dynamics 365, Teams, and websites where users already work.
  • Use AI for document and data processing — extraction, classification, summarization — with Foundry Tools (formerly Azure AI services) and AI Builder.
  • Keep humans in the loop for low-confidence results and high-impact decisions.

2.2 Design extensibility of AI solutions

Copilot Studio

  • Connectors and custom connectors for systems with APIs
  • Model Context Protocol (MCP) servers expose tools and resources in a standard way that agents can discover and reuse
  • Computer Use lets an agent operate a website or desktop app UI when there is no API
  • Reasoning models and voice for richer interactions

Choosing a path

  • API available → connector or MCP
  • Same tools needed by many agents → MCP server
  • No API, only a UI → Computer Use (with oversight)
  • Deterministic multi-step logic → agent flow

Microsoft 365 Copilot and Foundry extensibility

  • Agents in Microsoft 365 Copilot: declarative agents customize instructions, knowledge, and actions on the Copilot orchestrator; custom engine agents bring their own orchestration and models.
  • Publish agents to Teams and SharePoint so they meet users in context.
  • Microsoft Foundry provides model catalog, fine-tuning and custom models, Foundry Agent Service, and evaluation for pro-code builds.
Rule of thumb

Low-code makers and Microsoft 365 users → Copilot Studio or declarative agents. Developers needing model control → Foundry.

Exam trap

If a prebuilt capability meets the requirement, configure it rather than building a custom agent — less cost, faster delivery, and Microsoft maintains it.

Cheat sheet

Agent type

User asks → prompt-and-response or task. Event triggers → autonomous.

Routing

Many tools and messy phrasing → generative orchestration with good descriptions.

Reach

API → connector/MCP. UI only → Computer Use. Prebuilt first.
