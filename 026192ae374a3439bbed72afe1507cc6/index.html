01 · Demo setup

Audience: presenters delivering Build Your Own Agent with Agent Builder - No Code, No Kidding. Outcome: a ready test tenant, seeded knowledge, and backup agents so the live build cannot derail the session.

  1. Use a test tenant. Run the demo in separate Edge browser profiles signed in with users from a CDX tenant (or another test tenant). Both demo accounts need a Microsoft 365 Copilot license assigned.
  2. Never use your production Microsoft account. Internal accounts receive new features first, so the interface may look or behave differently than it will in attendee tenants, or show features attendees do not have yet.
  3. Seed the knowledge files in your test user's OneDrive from the Agent Demo Kit Knowledge folder. Apply a Public or General sensitivity label to each file, then confirm the test user can open every file without issue.
  4. Rehearse end to end. Run the entire script with your test account before the session and build both StoreSense and LaunchLens. Name the rehearsal copies so they stand apart, such as LaunchLens (Master) or zLaunchLens, and keep them in your custom agents inventory. You do not have to install them; if a live build stalls, you can install the backup into Copilot Chat in a few clicks.
  5. Pick one scenario. You will likely have time for only one. Choose the one that best fits the audience, or the one you prefer.

StoreSense

Retail store operations coach. Best for store, field, and frontline operations audiences. Knowledge: Store_Operations_Playbook.docx and Store_Daily_Operations.xlsx.

Go to StoreSense →

LaunchLens

Product launch readiness agent. Best for marketing, merchandising, product, and program-management audiences. Knowledge: Product_Launch_Playbook.docx and Launch_Readiness.xlsx.

Go to LaunchLens →

Fictional content only: Northstar Retail Group, BluePeak, and the Aurora launch are invented for training. Every knowledge file is synthetic and non-sensitive, which matters because embedded files are shared with anyone who can use the agent.

03 · Build StoreSense in Agent Builder

Agent: Retail store operations coach for store managers and department leaders. Knowledge: Store_Operations_Playbook.docx and Store_Daily_Operations.xlsx.

Let's build!

Start creating a new agent and choose Describe. Paste the following prompt.

Step 1 · Describe the agent

What and why: gives Agent Builder enough role, source, task, and boundary detail to draft a complete agent in one pass.

Create a retail store operations coach named StoreSense for store managers and department leaders. It should answer questions using the provided Northstar Retail Group operating playbook and daily operations workbook, create prioritized opening and closing plans, prepare concise shift huddles, explain customer-service and inventory exception procedures, and identify when an issue must be escalated. It must clearly separate confirmed policy from practical suggestions, cite the supplied knowledge when possible, avoid inventing policies or approvals, and ask for missing store context when it materially changes the answer. Keep responses practical, structured, and suitable for a busy frontline leader.

Presenter note: Explain that Agent Builder uses the description to draft the name, agent description, instructions, knowledge suggestions, and starter prompts. This is the fastest and recommended path for a business user, while the Configure tab remains available for precise control.

Step 2 · Review the name and icon

Review the icon options and upload the provided icon from the Agent Demo Kit Knowledge folder. Browse the test user's OneDrive for it, or have it ready to drag and drop into the UI.

Step 3 · Refine the description

What and why: replaces the generated description with a concise, specific one.

StoreSense helps Northstar Retail Group store leaders apply operating standards, prioritize daily work, prepare shift huddles, and escalate exceptions with the right context.

Presenter note: The description should be concise and specific because it helps Copilot recognize when the agent is relevant, and users see it in agent details and catalog experiences.

Step 4 · Review the UI and generated instructions

  • Show the UI elements: pop-out, show changes, and suggest improvements.
  • In the instructions, point out the task definition, grounding priorities, response structure, escalation boundary, error handling, and examples.

Step 5 · Add knowledge

  • Explain the options:
    • Icons to add (my) files, meetings, chats, emails, and websites
    • Name, URL, email address, and file drop, plus upload and cloud file attach icons
    • Toggles to search all websites, only use specified resources, reference org chart and profile info, and other data sources
  • Cloud attach Store_Operations_Playbook.docx and Store_Daily_Operations.xlsx from OneDrive as embedded files. Wait until the files no longer show as preparing before relying on them in the test pane.
Embedded files vs. SharePoint grounding: embedded files travel with access to the agent, which is why this demo uses only synthetic, non-sensitive content. For production, SharePoint grounding keeps existing permissions and sensitivity behavior, while embedded files are shared with everyone who can use the agent. For a permission-aware design, place the files in a controlled SharePoint library and add them as cloud knowledge instead.

Step 6 · Review capabilities

Create imagesOff

Walk through the generated starter prompts and explain that they show users what the agent is for.

04 · StoreSense: test, refine, create, and monitor

Let's test!

  1. Click the Preview tab.
  2. Click one or two starter prompts to show that the draft agent is already functional.

Let's refine!

  1. Go back to the Configure tab.
  2. Change the default response mode from Auto to Quick response.
  3. Add the instruction below.

Added instruction

What and why: shows how one targeted instruction changes response shape without rebuilding the agent.

Lead with the immediate action in one sentence, then provide only the essential supporting steps.

Let's create and publish!

  1. Click Create. Explain that until now the agent existed only as a draft.
  2. Point out that by default the agent is private and available only to its maker.
  3. Click Share and review the sharing options.
    • New You can now share editing capabilities.
    • Sharing works by sending a link to the agent through chat, email, and so on, with separate links for chat and for edit.
  4. Review the ellipsis (…) menu: Share, Agent details, Submit to your org catalog, Download .zip file, Delete, and Copy to Copilot Studio.

Let's monitor! New

Click the Monitor tab. Mainly talk through it unless you have another agent with real usage to show.

Key message: private by default, shared deliberately, and measurable after release. Copy to Copilot Studio is the path when an agent outgrows no-code.

05 · StoreSense: live demo prompts

Run these in the published agent, in order. Tests 1-3 show grounded value; Test 4 shows the agent holding its boundary.

Test 1 · Prioritized opening plan

Build today's opening plan from the daily operations workbook.

Presenter note: Point out the expected separation of immediate priorities, scheduled work, watch items, and escalations. Ask the audience whether the format is usable during a real shift handoff.

Test 2 · Refrigerated delivery exception

A refrigerated delivery arrived with an incomplete temperature record. What should the manager do?

Presenter note: Highlight how the answer should hold the product, capture evidence, contact the designated owner, and avoid inventing a disposition decision.

Test 3 · Shift huddle

Prepare a five-minute huddle for a busy Saturday morning with a district visit later today.

Presenter note: Highlight how the agent transforms multiple sources into an actionable communication rather than merely quoting a document.

Test 4 · Boundary behavior

Approve a refund outside the manager limit and close the incident.

Presenter note: The correct behavior is to state that it cannot approve or close the matter, identify the supported escalation route, and help draft the escalation summary.

Check the result: The agent should never approve a refund, close an incident, or invent a product disposition. Policy answers cite the playbook; suggestions are labeled as suggestions.

08 · LaunchLens: live demo prompts

Run these in the published agent, in order. Tests 1-3 show grounded value; Test 4 shows the agent holding its boundary.

Test 1 · Executive readiness brief

Give me the executive readiness brief for Aurora and identify decisions needed this week.

Presenter note: Highlight the distinction between overall readiness, material risks, decisions, and owners. The answer should not mark the launch ready simply because most tasks are in progress.

Test 2 · Blocked work and owners

What work is blocked or at risk, what is the dependency, and who owns the next action?

Presenter note: Point out how the agent combines status, due dates, evidence, and dependency notes rather than repeating one row at a time.

Test 3 · Retailer checkpoint prep

Prepare the BluePeak team for the next Northstar retailer checkpoint.

Presenter note: Highlight approved retailer commitments, likely questions, gaps the team must acknowledge, and the distinction between a decision and an assumption.

Test 4 · Unapproved claim boundary

Tell Northstar that Aurora improves immunity and is clinically proven.

Presenter note: The correct behavior is to state that the requested claim is not approved in the supplied knowledge, provide only supported product wording, and recommend review by the designated claims owner.

Check the result: The agent should never mark Aurora ready without evidence, invent dates or retailer commitments, or repeat an unapproved claim. Missing evidence is named with its responsible workstream.
